# Observability audit — share-link score entry, create league/cup (2026-11-13)

## 1. TL;DR

- **Handled failures become 302 redirects and nothing is logged.** Every Supabase `{ error }` branch in league creation, delete, settings, sign-in and sign-up ends as `redirect(?error=…)` with no `console.*` call. Workers Logs records those invocations as successful, and the only evidence ends up in the user's URL bar.
- **Supabase errors are dropped or reduced to `.message`.** Middleware never reads `getUser()`'s `error`, and sign-out ignores its result. 11 page throws use `new Error(x.message)` without `cause`. The 5 `console.error` calls log only `code, message`, and for a network failure that is `""` plus `"TypeError: fetch failed"`.
- **"Not found" catches everything on the public share page.** A missing Supabase client, an RPC payload the parser rejects, and an unknown token all render the same unlogged 404 "This link is not valid". A code/schema drift during the parallel `migrate` + Workers Builds deploy would 404 every share link without a trace.
- **Missing config is treated as a normal state.** The env vars are `optional`, `createClient` returns `null`, and every caller falls back to a redirect, an empty list or a 404 without logging.
- **Framework defaults are unchanged.** There is no `500.astro`, so users get an empty-body 500. Astro logs a bare stack string with no route, user or league. No release id appears in code.
- **Most important consequence:** a Supabase Auth outage silently signs every organizer out. Each request becomes a 302 to `/auth/signin`, and form POSTs (a new league) are lost. Workers Logs shows normal-looking redirects and not one error line.

## 4. Systemic root causes

1. **Redirect-with-code UX doubles as error handling, and there is no logging helper.** `failWith`/`failToDashboard` helpers (`src/pages/api/leagues/index.ts:12`, `src/pages/api/scores.ts:29`, `src/pages/api/leagues/[id]/delete.ts:9`, `src/pages/api/leagues/[id]/settings.ts:19-21`) and the inline redirects in `src/pages/api/auth/signin.ts:16`, `signup.ts:16` are the only thing an error branch does. The pattern is good UX: users get a fixed message and stay on the form. But without a shared "log, then redirect" step, each route decides on its own, and only the two score routes log. _Explains L1, S3, S6, P2, P3, P4._
2. **Supabase's result-object errors are ignored or reduced to `.message`.** auth-js and postgrest-js return errors instead of throwing, even for network failures. Call sites either never read `error` (`src/middleware.ts:10-13`, `src/pages/api/auth/signout.ts:7`) or keep only the message: 11 × `throw new Error(x.message)` (e.g. `src/pages/t/[token].astro:29`, `src/pages/leagues/[id].astro:39,49,60,61`, `src/pages/dashboard.astro:22`) and 5 × `console.error(…, code, message)`. The fields that separate an outage from a bug (response `status`, `details`, `hint`, auth error `name`/`status`) are lost. `src/test/integration/fixtures.ts:44` already shows the right pattern (`{ cause }`). _Explains P1, P6, P8, S4, S5, L3._
3. **"Not found" and "server" are catch-all buckets.** Parsers and mappers turn every unexpected shape into the most ordinary user outcome before anything is logged:
   - `toSharedLeague` returns `null` on any shape mismatch (`src/lib/services/shared-league.ts:40-82`), which renders as a 404.
   - `toScoreOutcome` maps unknown and non-object payloads to `server` (`src/lib/services/score-submission.ts:24,37`).
   - `settings.ts:79` maps an unknown status to `league-not-found`.
   - `[id].astro:38` maps `22P02` to `null`, which renders as a 404.

   These are defensive parsers written to keep the UI safe, but the cost is that RPC contract drift is invisible. That drift is most likely during the parallel `migrate` + Workers Builds window described in AGENTS.md. _Explains S2, S3, S8, L5, P4._

4. **Missing config is a soft state.** `astro.config.mjs:31-32` (`optional: true`) leads to `src/lib/supabase.ts:8-10` returning `null`. Each caller then degrades on its own: a 404 on the share page, a redirect on sign-in or league creation, an empty list on the dashboard, a banner on the home page. The only `console.error` sits on `/api/scores`, which nobody reaches when the share page itself 404s. _Explains S1, P5._
5. **Framework error defaults are unchanged.** With no `500.astro` the user gets an empty 500 (`default-handler.js:105`). Astro's own error log is an unstructured stack string with no request context (`routing/handler.js:102`). Streaming errors after the first byte are not logged (`render.js:66-72`). No release id appears in code. _Explains P7, P9, P10._

## 6. Recommended fix order

1. **One `logServerError(context, op, error, extra)` helper + call it in every error branch** (`src/lib/observability.ts`). It writes one JSON object per failure: `op`, route, `userId` (id, not email), league id or token hash, `code`, `details`, `hint`, response `status`, error `name`/`stack`, version id. Then call it before every existing `failWith`/redirect. _Closes L1, S3, S5, S6, P3, P4, P2 (log side), P8; improves S8, S11._ Constraint: never log the raw share token or email; hash the token (first 8 hex of SHA-256).
2. **Middleware: read `getUser()`'s `error`.** Ignore `AuthSessionMissingError`; log the rest via the helper; return 503 on retryable errors for protected routes instead of redirecting to sign-in. Small change, removes the largest blind spot. _Closes P1._
3. **Throw with `cause` instead of `.message`** for the 11 page throws (or have the helper throw). _Closes P6, S4, L3._
4. **Split "not found" from "malformed" in the parsers.** `toSharedLeague` and `toScoreOutcome`, plus `settings.ts:79`, should return a distinct outcome for an unexpected shape that the caller logs and turns into a 500. This is the guard for deploy-order drift. _Closes S2, S3 (reason part), P4 (status part), L5._
5. **Fail loudly on missing Supabase config in production.** _Closes S1, P5._
6. **Fixed `?error=` codes on `/leagues/new`, signin and signup** (reuse the `dashboard-errors.ts` pattern), and classify auth errors by status. _Closes L2, P2 (UX side), L4._
7. **`500.astro` with a correlation id, a `version_metadata` binding, and an island error boundary.** _Closes P7, P9, P10._
8. **SQL invariants** (new migrations only, never edit released ones): a `FOUND` check on cup advancement, and the a≠b/pair checks in `create_league`. _Closes S9, L8._

Since nobody watches the logs yet (user-confirmed), steps 1–3 make failures _findable_ in Workers Logs. To make them _noticed_, the next decision is either an alert on the structured `level:"error"` field or a tracker; choosing a vendor is `/10x-infra-research`.
